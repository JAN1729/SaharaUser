# Jev mobility decision integration

Implement the user's supplied hybrid design in the existing Python server using OpenRouter's Decisions API and the existing protected OpenRouter credential. Kotlin remains the passenger interface. No transport inventory API is introduced.

1. Shared async client: pinned `typesafe/jev-1.13`, fixed HTTPS endpoint, typed response validation, bounded concurrency and deadlines, content-addressed cache, outage cooldown, usage/latency diagnostics. Do not send passenger identifiers or GPS traces.
2. Reconciliation: normalize common stop abbreviations, shortlist by proximity and explicit operational identity/corridor/direction, reject contradictory IDs, sequence or service date. Preserve source records and record an auditable match/review/different result. Semantic-only matches remain review proposals by default until calibrated with labeled operator data. Local server-owned timetable feeds may supply stop records and canonical references; only accepted bindings change endpoint IDs. Never infer a vehicle association from a stop-name match.
3. Notice triage: validate source/time and explicit corridor scope in code, classify notice kind/relevance/ambiguity in one Jev request, and persist an owner-bound decision. Only the existing verifier may emit a journey change. The watch worker processes pending notice decisions with its existing lease/stop protections; uncertain notices retain their review status and do not mutate itineraries.
4. Intent routing: clear complete route requests can use the validated rules parser without a model. Jev classifies ambiguous chat intent; only validated planning/constraint requests use the rules shortcut, otherwise existing extraction remains the fallback. No unsupported handler is silently called. Exact monetary extraction, accessibility requirements and preference scoring stay in code.
5. Evaluation: focused regression tests, a small explicitly synthetic decision probe with actual OpenRouter cost/latency, and a labeled-data evaluation command reporting false matches, missed matches, review rate and latency. Synthetic probes do not establish production accuracy or end-to-end speed improvements.

Execution: implement and verify inline, preserving the dirty workspace. Server-only changes keep the current APK compatible. Restart the owned local server after regression checks and verify health and existing API smoke checks.

Sources checked: [OpenRouter Jev guide](https://openrouter.ai/docs/guides/community/jev), [Decisions API](https://openrouter.ai/docs/api/api-reference/alphadecisions/submit-a-decisions-request), [TypeSafe confidence](https://docs.typesafe.ai/confidence), [Jev limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13). Model confidence is not service reliability or source truth.
